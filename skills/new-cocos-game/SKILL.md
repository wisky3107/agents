# New Cocos Game

One-shot bootstrap for a **new** Cocos Creator game from the local template.
Do not use on an existing repo — use `/update-skills` / `/setup-project` there.

**Do not** run `cocos create`. **Do not** install from `agent-skills/cocos-creator`.
The template already contains the Cocos project, workflow skills, and
`.cursor/skills` / rules / `AGENTS.md`. (3.8 templates also ship Funplay under
`extensions/`; cc4 does not — it uses COCOS 4 CLI MCP.)

Copy via `rsync`, **including `library/`** (faster first Creator open) and the
template **`build/` scripts** (`build.sh`, `deploy.sh`, `build-configs/`,
`scripts/postbuild.mjs`). Exclude: `temp/`, `local/`, `profiles/`,
`build/web-mobile/`, `build/.vercel/`, `node_modules/`, `.git` (never inherit
template history — always fresh `git init`), `.DS_Store`. After copy, delete
any leaked `.git` before `git init`. For **cc4**, exclude machine-local MCP pin/client configs so
`mcp-config` / `resolve-ports` regenerates them (same as Funplay).

Resolve Orca per the `orca-cli` skill. Prefer `--json`.

## Step 0 — Intake (always first)

Ask only what's missing:

1. **Project folder name** (slug): prefer `cc-<name>` (or `cc4-<name>` when using the cc4 template)
2. **Template**: default `cc-game-template`. Keyword picks (do not ask; announce in one line):
   - **"cc4"** / **"COCOS 4"** / **"cocos 4"** (any casing) → `cc4-game-template` via `--template cc4`
     (`Template: cc4-game-template (prompt says "cc4")`)
   - else **"playable"** (playable ad, playable slice, "tạo playable") →
     `cc-playable-template` via `--template playable`
   - Honor an explicit template name / `--template` value over the keyword.
     If both `cc4` and `playable` appear, prefer **cc4** (no cc4-playable template).
3. **Brief** → becomes `GAME_BRIEF.md`
3b. **Brief author** (announce in one line, do not ask):
   - `fable` — when the user says **fable** / "brief sâu" / "contracts" / "HOW_TO, EXPECT",
     supplies reference media (screenshots, video, GDD, GLB folder) or a gameplay video
     file / URL, **or** mode=`fleet` (the fleet reviews against `EXPECT_GAMEPLAY_VISUAL.md`'s
     feel table). Source = `media` when a folder or a video was given, else `idea` (the brief
     text). Pass a video URL on to `game-brief`, which fetches and probes it with the
     `gameplay-video` skill.
   - `inline` — otherwise (current behaviour: `/setup-project` Phase 0 seeds `GAME_BRIEF.md`).
   - Keep `brief_author=fable` as the legacy routing value for the `game-brief` workflow;
     it does not force the model. A request for `game-brief` or deep contracts using another
     agent also selects this route. Pass the explicit brief agent/model to `game-brief`, which
     resolves explicit choice → saved `brief.brief_agent` → Fable 5.1.
   - Honor "brief nhanh" or an explicit request to skip deep contracts as `inline`.
     "No Fable, use another model" selects deep contracts with that model.
3c. **Release goal** (announce in one line, do not ask) → `AGENT_NOTES.md` `release.goal`:
   - `end_to_end` — **default**: producer runs every slice in `MILESTONES.md`, then ships.
   - `playable` — user says "bản chơi được trước" / "playable first" / "chỉ cần chơi được" /
     "v1 thôi" / "prototype": producer stops after `v1_slice` is APPROVED + committed
     (+ preview URL when `release.deploy != none`, never prod).
   - `release.deploy`: default `preview`; "lên prod" → `prod`; "không deploy" / playable-ad
     template → `none`.
4. **Implement now?** yes / no
5. **Implement mode** (if implement=yes):
   - `producer` — **default when brief_author=`fable`**: orchestrator agent runs
     `game-producer` in the project (slice loop → fleet/single lanes → commit/merge → ship
     per `release.goal`). Triggers: "producer", "end to end", "chạy hết", "tới release".
   - `single` — one agent runs `vibe-game-director` (default when brief_author=`inline`)
   - `fleet` — orchestrator runs `cocos-orca-fleet` for **one** slice/feature (triggers:
     user says fleet / orchestrator / cocos-orca-fleet / multi-agent / "team" / "1 slice thôi")
6. **Orca agent** (if implement=yes): default **`cursor --model auto`** when the
   user does not name an agent. This is the **orchestrator** when mode=`producer` or `fleet`
   (and the single implementer when mode=`single`). Do not ask; only override if
   they said `claude` / `codex` / `antigravity` / another agent explicitly.
   Capture a named model too ("orchestrator claude opus" → `--agent claude --model opus`;
   "cursor gpt-5 high" → `--agent cursor --model gpt-5 --effort high`). Preview the
   resulting command with `bootstrap.mjs agent-cmd --agent … --model …` when unsure.
7. **Fleet workers** (only if mode=`producer` or `fleet`, never ask): if the user names an agent
   for the *workers* / *scanner* / *writer* / *reviewer* / *planner* ("fleet dùng cursor agent", "reviewer
   claude opus", "planner codex", …) record it for `AGENT_NOTES.md` `fleet.writer_agent` /
   `fleet.reviewer_agent` / `fleet.planner_agent` / `fleet.scanner_agent`; a bare "cursor agent" → `cursor --model auto`.
   If they name nothing, leave the skeleton defaults (`claude --model opus …`) untouched.
   Same for `art_backend` (default `antigravity`).
8. **Data owner** (only when `~/.orca-memory/bin/orca-memory` exists): who owns the game's data
   (e.g. `internal`), for Step 6a. Ask in the same intake message as any other missing item;
   never guess it and never leave it to the end of the run.

Do not invent a brief. No brief → still copy + register + open + MCP gate + commit,
then stop before Step 6b / setup-project.

### Hard rule — producer / fleet orchestrator lives in the new project

When mode=`producer` or `fleet` / user asks for `game-producer` / `cocos-orca-fleet`:

- **Never** run the producer or fleet coordinator from this bootstrap chat (wrong cwd /
  wrong repo / wrong Orca worktree).
- **Always** spawn the orchestrator via `bootstrap.mjs agent-session` with

  `--worktree path:<newProjectPath>`.
- That session is the coordinator; workers it starts must also target that
  project's worktrees (`path:<project>` / child worktrees of it).
- Bootstrap chat only reports the terminal handle and stops.

### 3.8 templates (default / playable)

Default: opens Creator and **blocks** until Funplay `/health` on the project's pinned port
reports `projectName == <slug>`. Exit code **3** if that never happens — do not continue
to setup/implement.

What it does:

1. `rsync` the selected template (`--template`, default `cc-game-template`) → `/Users/wikz/Works/games/CocosCreator/<slug>`
2. Set `package.json` `name` to the slug
3. `git init` (+ `main`)
4. Pre-seed Cursor + Claude + Codex workspace trust (skip "trust this project")
5. **Pin a Funplay port** for this checkout: first free port in 8765..8799 that no other
   checkout (games root siblings, git worktrees) has pinned and no live Creator of another
   project is serving → `funplay-cocos-mcp.config.json`; write project-local
   `.cursor/mcp.json`, `.mcp.json`, `.codex/config.toml` pointing `funplay_cocos` at it
6. `orca repo add --path <project>`
7. Launch Creator: `<binary> --project <path> --nologin` (Funplay reads the pin and binds it)
8. Poll `/health` on that port until `projectName == <slug>`. If another project answers
   there and ours is found on a different port, configs are re-pointed automatically
   (`repointed: true` in the result)

Another game's Creator being open is **fine** — it keeps its own port. What is never fine
is treating "8765 answers" as success; the JSON result carries `projectName`, `port`,
`repointed` — report them.

If MCP stays down: tell the user to start **Funplay → MCP Server** in Creator, then:

```bash
node ~/.agents/skills/new-cocos-game/scripts/bootstrap.mjs wait-mcp --path <projectPath>
```

If the result says `otherProjectOnPort`, that Creator got there first: close it or
`bootstrap.mjs mcp-config --path <projectPath>` to pin another port, restart Creator, `wait-mcp`.

### Step 6a — Memory registration

Skip only when `~/.orca-memory/bin/orca-memory` does not exist. Otherwise this step is required:
an unregistered project runs every later memory hook as `off` without a word (cc-lego-stack went
S01–S08 that way). Run once:

```bash
M=~/.orca-memory/bin/orca-memory; [ -x "$M" ] && "$M" register --path <project> --domain cocos \
  --engine <engine_version> --stack-mode <2d|3d> --target <web-mobile|...> --data-owner <owner>
```

`--data-owner` comes from intake item 8; never guess it. If the user would not give one, do not
register; say so in the final report with the command above so the operator can run it. The
command appends the project with memory mode `off` and refuses a duplicate id or an overlapping
path; that refusal is not a bootstrap failure. Leave out any fact you do not know (engine, mode,
target) rather than guessing. Report the printed `{"registered":…}` line (or the refusal) in the
final message. Turning memory on is a separate, deliberate operator edit of
`~/.orca-memory/config/projects.json`; never do it here. `orca-memory doctor` lists active
checkouts that were never registered.

## Step 8 — Implement via Orca (or stop)

**Implement = no** → report path, Creator/CLI version, Orca id, MCP port + confirmation,
and that `AGENT_NOTES.md` holds them. Stop.

**Implement = yes** → hand off (do not build / do not orchestrate in this chat):

```bash
node ~/.agents/skills/new-cocos-game/scripts/bootstrap.mjs agent-session \
  --path <projectPath> \
  [--agent cursor|claude|codex|antigravity | "<spec from AGENT_NOTES.md fleet.orchestrator_agent>"] \
  [--model <m>] [--effort <e>] \
  [--title "implement-<slug>" | "fleet-<slug>" | "producer-<slug>"] \
  [--role coordinator | producer | worker] [--slice S01] \
  [--prompt "<prompt>"]
```

`--role`: mode `fleet` → `coordinator --slice S01` (launches without the editor's MCP tools; the
coordinator never edits through Funplay); mode `producer` → `producer` (keeps Funplay for post-merge
parity on main); mode `single` → `worker`. `--slice` needs a `--role`.

Pass `--agent "$(yq '.fleet.orchestrator_agent' …)"`-style spec strings verbatim, or the id plus
`--model` / `--effort`; explicit flags win over the spec. The JSON result's `session.agentSpec`
is the canonical string — if it differs from `AGENT_NOTES.md` `fleet.orchestrator_agent`, update
the file so it records what was actually launched.

`agent-session` always binds `--worktree path:<projectPath>` — required so the
agent (single implementer **or** fleet orchestrator) cwd/repo is the new game.
Pre-trusts **Cursor, Claude, and Codex** for that path (and every Orca child
worktree via `scripts/setup-orca-worktree.sh`), makes sure the project-local MCP
client configs exist (runs `mcp-config` if the checkout has no pin yet), waits
`tui-idle`, then sends prompts. Launch flags skip the interactive trust/approval gate.

**Boot is conditional:** Cursor and Codex load rules natively. Claude and Claude Agent
Teams skip the separate boot when `CLAUDE.md` exists (verify it imports `AGENTS.md` in the
template); otherwise they receive the startup prompt. Other agents receive it by default.
`--boot` / `--no-boot` override this choice. Wait for TUI readiness before any prompt.

**Art gen agents do not get this boot.** Fleet art Tasks (`art-concept-*`, `art-mesh-*`,
`art-2d`) use `cocos-orca-fleet` recipe **C** and start on their art spec. Do not route art
workers through `agent-session` just to force a boot.

| `--agent` | Orca settings command | Trust seed |
|-----------|----------------|------------|
| `cursor` (default) | `cursor-agent --yolo --model <m|auto> [--effort e]` (never `cursor` IDE; `--effort` dropped when model is `auto`) | `~/.cursor/projects/<slug>/.workspace-trusted` |
| `claude` | `claude [--model m] [--effort e] --dangerously-skip-permissions` | `~/.claude.json` `hasTrustDialogAccepted` |
| `codex` | `codex --dangerously-bypass-approvals-and-sandbox [--model m] [-c model_reasoning_effort=e]` | `~/.codex/config.toml` `[projects."path"] trust_level = "trusted"` |
| `antigravity` | `agy --dangerously-skip-permissions` (model/effort ignored) | `~/.gemini/trustedFolders.json` + Antigravity trusted workspaces |
| `claude-agent-teams` | `orca claude-teams --dangerously-skip-permissions` | Claude trust seed |
| `gemini` | `gemini --yolo` | provider CLI |
| `opencode` | `opencode` | provider CLI |

Launch permissions follow the Orca settings baseline confirmed by the user. Trust seeding
only accepts the workspace; it does not grant tool approval or disable a sandbox. Custom
`terminal create --command` uses the supplied command; do not assume it inherits settings.
Use `bootstrap.mjs agent-cmd --agent "<locked spec>" --json` to resolve/inspect custom commands.
The additional supported providers are `claude-agent-teams` → selected Orca executable +
`claude-teams --dangerously-skip-permissions`, `gemini` → `gemini --yolo`, and `opencode` →
`opencode`. Teams keeps its provider identity. Gemini/OpenCode currently reject model/effort
rather than silently dropping them. This mapping is a baseline, not a live settings sync;
if the user changes Orca settings, reconcile the launcher before dispatch.
After `agent-session`, require `ok=true` and `session.promptSent=true` when a task was supplied.
Failure retains the handle for diagnosis/recovery; do not blindly rerun and create a duplicate.
Existing sessions keep their original permissions until replaced after work has stopped.

## Failure notes

| Problem | Action |
|---------|--------|
| Template missing | Fail; path must exist |
| Target exists | Abort; pick another slug |
| Orca down | `orca open --json`, retry |
| Creator won't open (3.8) | Fix binary; still can `wait-mcp` after manual open |
| `cocos` CLI missing (cc4) | Install/add COCOS 4 CLI to PATH; then `./scripts/open-mcp.sh` |
| **MCP down** (3.8: no Funplay `/health`) | User starts Funplay → MCP Server; re-run `wait-mcp`; **do not** continue setup/implement until ok |
| **MCP down** (cc4: no initialize on pinned port) | `./scripts/open-mcp.sh`; re-run `wait-mcp`; do not continue until ok |
| **Wrong project on our port** (`otherProjectOnPort`, 3.8) | Another Creator bound it first. Close that Creator, or `mcp-config --path <project>` → new pin → restart this Creator → `wait-mcp`. Never proceed against a port serving a different `projectName` |
| Two games open at once (3.8) | Supported: each checkout has its own pinned port and local MCP configs. Only the `projectName` gate matters |
| Two cc4 checkouts | Supported: each pins MCP (9527–9559) + preview (7456–7489). Run `mcp-config` / `open-mcp.sh` per checkout; probe the pinned URL |
| Cursor/Claude/Codex/Antigravity "Trust this project?" | `bootstrap.mjs trust --path <abs>` seeds Cursor + Claude + Codex **and** Antigravity (`~/.gemini/trustedFolders.json` + `antigravity-cli` `trustedWorkspaces`). Worktree hook `scripts/setup-orca-worktree.sh` seeds the same for every child worktree. Antigravity still launches with `agy --dangerously-skip-permissions`. Never send before `tui-idle` |
| User asked fleet/producer but agent opened elsewhere | Abort handoff; re-run `agent-session --path <projectPath>` — orchestrator must be in the new project |
| mode=producer but no `MILESTONES.md` / `slices/` | Run Step 6b (`game-brief`) first, or fall back to `single`/`fleet` and say so |
